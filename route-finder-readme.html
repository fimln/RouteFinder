RouteFinder

Shortest-path search on the OpenStreetMap walking network around Universitas Gadjah Mada, Yogyakarta. Pick a start and a goal on the map, watch the algorithm explore.

branch: branch_ali Python 3.9+ Flask OSMnx Leaflet.js A* Genetic Algorithm
TL;DR. Flask backend loads a cached OSM walking graph (10 km around UGM), runs either A* or a Genetic Algorithm between two clicked points, and streams the explored nodes plus the final path back as JSON. A vanilla-JS Leaflet frontend animates the search, then draws the route. The branch_ali branch adds the GA option alongside the original A*.

Overview

RouteFinder is a small teaching project that contrasts two search strategies on the same real-world graph:

A* deterministic

Best-first search with a Haversine heuristic. Guaranteed optimal, expands fewer nodes than Dijkstra.

Genetic Algorithm stochastic

Population of biased random paths, evolved by tournament selection, crossover at shared nodes, and segment mutation.

The frontend picks the algorithm via a dropdown, then animates each explored node with a tooltip carrying its f, g, h scores (A*) or a GA marker.

Algorithms

A* deterministic

Each node gets a score:

f(n) = g(n) + h(n)
  • g(n): actual distance accumulated from the start node to n, summing edge lengths.
  • h(n): Haversine distance from n to the goal, a great-circle lower bound.
  • f(n): the priority used to order the open set.

The heuristic never overestimates (no road is shorter than a straight line on the sphere), so it is admissible and A* returns the optimal path.

Genetic Algorithm stochastic

The GA in backend/ga.py treats each candidate route as a chromosome and evolves a population of them.

  1. Seeding. The first population member is guaranteed via nx.shortest_path (length-weighted). Remaining slots are filled by generate_random_path, which walks from start, at each step ranking neighbors by Haversine distance to the goal and picking one of the top three. This biases the population toward feasible directed paths instead of pure noise. The walk gives up if it dead-ends or exceeds 2000 nodes.
  2. Fitness. Sum of edge lengths along the path. Shorter is fitter.
  3. Selection. Tournament of 3, repeated for both parents.
  4. Crossover (p = 0.7). Pick a node that appears in both parents and splice prefix of parent 1 with suffix of parent 2. If the resulting path would contain a cycle (duplicate nodes), fall back to parent 1.
  5. Mutation (p = 0.3). Cut at a random interior index, then call generate_random_path to redraw a segment to the goal.
  6. Elitism. Top two paths survive untouched into the next generation.

Defaults: pop_size=10, generations=20. The best path across all generations is returned.

Show seeding + evolution loop (backend/ga.py) 
# 1. Inisialisasi Populasi (shortest path sebagai jaminan)
try:
    shortest = nx.shortest_path(graph, start_node, end_node, weight="length")
    population.append(shortest)
except nx.NetworkXNoPath:
    raise ValueError("GA gagal menemukan rute awal yang valid.")

# Tambahkan rute acak berbias untuk mengisi populasi
for _ in range(pop_size * 3):
    if len(population) >= pop_size:
        break
    p = generate_random_path(graph, start_node, end_node, explored_order)
    if p and p not in population:
        population.append(p)

# 2. Siklus Evolusi
for gen in range(generations):
    pop_fitness = [(p, calculate_path_distance(graph, p)) for p in population]
    pop_fitness.sort(key=lambda x: x[1])

    if pop_fitness[0][1] < best_dist:
        best_path = pop_fitness[0][0]
        best_dist = pop_fitness[0][1]

    elite_count = min(2, len(pop_fitness))
    next_gen = [pop_fitness[i][0] for i in range(elite_count)]
    while len(next_gen) < pop_size:
        parent1 = min(random.sample(pop_fitness, min(3, len(pop_fitness))), key=lambda x: x[1])[0]
        parent2 = min(random.sample(pop_fitness, min(3, len(pop_fitness))), key=lambda x: x[1])[0]
        child = crossover(parent1, parent2) if random.random() < 0.7 else parent1
        if random.random() < 0.3:
            child = mutate(graph, child, end_node, explored_order)
        next_gen.append(child)
    population = next_gen

HTTP API

GET /api/graph-info

Returns the map center, supported radius, and graph size. Used by the frontend to set the initial Leaflet view.

{
  "center": [-7.7713, 110.3776],
  "radius_m": 10000,
  "node_count": 12345,
  "edge_count": 34567
}

POST /api/route

Body:

{
  "start":     [lat, lon],
  "end":       [lat, lon],
  "algorithm": "astar"   // or "ga"
}

Coordinates are rejected with HTTP 400 if they fall outside a bounding box derived from AREA_CENTER and AREA_RADIUS_M. A graph with no connecting path yields HTTP 404.

Response:

{
  "path": [[lat, lon], ...],
  "distance_m": 1234.5,
  "nodes_explored": 287,
  "explored_coords": [
    { "lat": ..., "lon": ..., "f": 812.3, "g": 410.1, "h": 402.2 },
    ...
  ]
}
Note on the request field name

Earlier on this branch the backend read the choice from body.get("ga", "astar") while the frontend sent algorithm, so the GA path never fired. The backend has been updated to read body.get("algorithm", "astar") so both sides agree.

Frontend UI

One Leaflet map, one side panel, one legend. State machine in map.js walks through three phases:

  1. awaiting_start, then awaiting_end, then done.
  2. On the second click the panel posts to /api/route and switches the status text to Mencari rute….
  3. animateExploration drops one orange circle per explored node, refreshes a yellow highlight on the current one, and updates the f g h score box (A* only).
  4. drawResult fades the exploration trail and overlays the final polyline.

What is new on branch_ali

Compared with master, this branch adds the Genetic Algorithm path and the UI wiring for it.

Bug fix: GA now always seeds a valid population

Previously, generate_random_path could fail on every attempt in graphs with many dead ends (typical for walking networks), producing an empty population and raising ValueError("No path found between the selected points."). The fix seeds the first population member with nx.shortest_path(graph, start, end, weight="length"), guaranteeing at least one valid path. The crossover function was also hardened against producing cyclic paths.
